title: Lynx CLI
description: Reference for building and publishing managed Lynx releases.

Run these commands from the Expo host project root.

| Command | Purpose |
| --- | --- |
| `pnpm lynx console` | Start the local Console and Cloudflare Worker runtime at `http://127.0.0.1:8787`. |
| `pnpm lynx console setup --username <username>` | Sign in to Cloudflare, provision or reuse D1/R2, deploy the Worker, and write the local `.env.lynx` connection values. |
| `pnpm lynx bundle <feature>` | Build the embedded fallback and calculate its Expo native runtime fingerprint. Use before building a new native app binary. |
| `pnpm lynx release <feature>` | Build, package, upload the immutable release to R2, and register it with the configured Worker. It does not enable the bundle. |
| `pnpm lynx release upload <release-directory>` | Upload a release made earlier with `--draft`. |

## Normal remote update

```sh
pnpm lynx release delivery
```

Open the Console, choose the correct app, feature, and runtime scope, then
select the new bundle and enable it. `force: false` stages it for the next
feature open; `force: true` reloads a mounted matching feature after a verified
install.

## New native app binary

```sh
pnpm lynx bundle delivery
npx expo prebuild --platform ios
```

`bundle` calculates the Expo native fingerprint and writes it into the embedded
registry. The released remote bundle must carry that same runtime fingerprint.
Later `pnpm lynx release delivery` reuses the registry value; it does not
silently calculate a different runtime from a changed working tree.

## CLI credentials

The ignored `.env.lynx` holds the Worker URL, your API key, and R2 S3 upload
credentials. The CLI needs those to upload. It never needs the Worker's
`DELIVERY_SIGNING_PRIVATE_KEY`; only the Worker signs deployment responses.
