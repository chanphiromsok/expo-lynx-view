---
title: Installation
description: Install Expo Lynx and configure a host application's safe baseline.
---

Expo Lynx runs in an Expo development or release build, not Expo Go. Each
managed mini-app has an embedded bundle that always works offline; remote
delivery only replaces it after verification.

## 1. Add the module and CLI

```sh
pnpm add expo-lynx-view
pnpm add -D expo-lynx-bundle-cli
```

## 2. Configure the host plugin

Before replacing the example URL below, provision the shared Worker and
register the app/mini-app IDs with the [Cloudflare Console](/managed-delivery/cloudflare-worker/#first-time-cloudflare-setup).

```json
{
  "expo": {
    "plugins": [["expo-lynx-view", {
      "embeddedBundlesPath": "./generated/expo-lynx/embedded",
      "publicKeyPath": "./keys/lynx/updates.public.pem",
      "deliveryEndpoints": {
        "merchant-home": "https://your-worker.workers.dev/v1/bs-one/merchant-home"
      }
    }]]
  }
}
```

The generated embedded directory contains only the approved local fallback
bundles. The host project does not contain mini-app source or a feature map.
Embed each mini app once, then prepare the native compatibility record before
the native archive:

```sh
pnpm lynx host embed ../merchant-home
pnpm lynx host prepare --register
```

Then run the normal native build without changing native dependencies or the
Expo Lynx configuration between preparation and the build. See [Host app
integration](/managed-delivery/host-app-integration/) for the complete flow.

:::note[When a new native build is needed]

Prepare and distribute a new app binary after changing native inputs: an
embedded baseline, native dependency, Expo plugin, public key, or endpoint.
Publishing an ordinary remote release does not need a native rebuild.

:::

## 4. Render the managed feature

```tsx
<ExpoLynxView source={{ kind: 'managed', feature: 'delivery' }} style={{ flex: 1 }} />
```

The first launch renders the embedded baseline. Later launches synchronously
render a compatible verified cache when one exists, then check the Worker in
the background.

See the [ExpoLynxView reference](/reference/expo-lynx-view/) for props and
events.

## 5. Warm the runtime before the first mount

The first `ExpoLynxView` mount starts a background JS engine. Do that work
early, once the app is interactive:

```tsx
import { InteractionManager } from 'react-native';
import ExpoLynx from 'expo-lynx-view';

InteractionManager.runAfterInteractions(() => {
  ExpoLynx.prewarmRuntime();
});
```

Calling it when the user opens the screen that contains the Lynx view is even
better. See [First-render performance](/managed-delivery/performance/).
