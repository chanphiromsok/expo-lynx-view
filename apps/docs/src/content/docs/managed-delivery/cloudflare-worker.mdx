---
title: Cloudflare Worker and data plane
description: One Worker, D1 database, and R2 bucket for all host apps and mini-app features.
---

`apps/console` ships one TanStack console and one Elysia Cloudflare Worker. It
serves many host apps and mini-apps:

```text
appId + feature + runtimeVersion → selected immutable bundle
```

## First-time Cloudflare setup

This command provisions the shared delivery Console. Run it once from this
repository, not from every Expo host app.

### 1. Prepare the Worker signing key

The Worker must sign public deployment responses with the private half of the
public key compiled into the mobile app. Put the PEM in the ignored local file:

```dotenv title="apps/console/.dev.vars"
DELIVERY_SIGNING_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----
...your PKCS#8 RSA private key...
-----END PRIVATE KEY-----"
```

The setup command derives its public key and stops if it does not match
`apps/expo-lynx-example/keys/lynx/updates.public.pem`. Never put this private
key in an Expo app, `.env.lynx`, a Git commit, or an R2 bucket.

### 2. Create the R2 S3 upload credential

In Cloudflare Dashboard, open **R2 → Manage R2 API Tokens**, or use the URL
printed by setup. Create an **R2 S3 API token** with:

| Setting | Value |
| --- | --- |
| Permission | **Object Read & Write** |
| Bucket | `lynx-artifacts`, or the bucket configured in `apps/console/wrangler.toml` |
| Use | CLI upload from developer machines |

Keep its access-key ID and secret access key private. This is an S3 credential,
not a general Cloudflare API token. The Worker does not receive it.

### 3. Run setup and authorize Wrangler

```sh
pnpm lynx console setup --username your-console-name
```

If Wrangler is not signed in, it opens a browser for Cloudflare OAuth and then
lists your accounts. Choose the account, paste the R2 S3 access-key ID, then
paste the secret at the hidden prompt. Wrangler OAuth needs account/user read,
D1 write, and Workers write to create the shared infrastructure.

Setup then creates or reuses D1 and R2, deploys the Worker, writes Worker
secrets, applies D1 migrations, and writes the ignored root `.env.lynx`:

```dotenv title=".env.lynx"
CLOUDFLARE_ACCOUNT_ID="..."
R2_ACCESS_KEY_ID="..."
R2_SECRET_ACCESS_KEY="..."
LYNX_DELIVERY_SERVER="https://your-worker.workers.dev"
LYNX_DELIVERY_API_KEY="lynx_live_..."
LYNX_DELIVERY_USERNAME="your-console-name"
LYNX_DELIVERY_PASSWORD="generated-password"
LYNX_DELIVERY_R2_BUCKET="lynx-artifacts"
```

Do not commit `.env.lynx`. It is the private handoff file for future releases.

### 4. Point the native app at the deployed Worker

Use the public deployment URL in the Expo plugin, then make a new native app
binary because the endpoint is a native configuration value:

```json
{
  "deliveryEndpoints": {
    "delivery": "https://your-worker.workers.dev/v1/default/delivery"
  }
}
```

After that one-time setup, publishing a normal bundle is only:

```sh
set -a
source .env.lynx
set +a
pnpm lynx release delivery
```

Open the deployed Worker URL, sign in with the generated console credentials,
and select then enable the uploaded bundle for its app, feature, and runtime.
The CLI upload itself does not enable a release.

| D1 table | Purpose |
| --- | --- |
| `bundles` | Immutable verified ZIP metadata, including app, feature, and runtime fingerprint. |
| `deployments` | Selected bundle, enabled state, force flag, and revision for one runtime scope. |
| `users` | Console username/password and hashed CLI API key. |

Public mobile routes require no user credential:

```text
GET /v1/:appId/:feature
GET /v1/:appId/:feature/:releaseId/release.zip
```

The deployment response is signed by `DELIVERY_SIGNING_PRIVATE_KEY`; its public
counterpart is embedded in the app. The CLI uploads directly to R2 with local
S3 credentials, then asks the Worker to verify exact ZIP size and SHA-256
before D1 registration. The Worker never receives an R2 S3 secret.

Clients without `lynx-runtime-version` are supported only while one deployment
is unambiguous. This temporary bridge fails closed once multiple runtimes exist.

## Later Worker changes

Deploy Console/Worker code changes without recreating D1, R2, users, or API
keys:

```sh
pnpm --filter @expo-lynx/delivery-console run deploy
```

Use `console setup --dry-run --username your-console-name` to check local key
prerequisites without changing Cloudflare. Setup intentionally refuses to
overwrite an existing `.env.lynx`.
