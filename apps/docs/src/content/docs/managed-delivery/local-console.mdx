title: Delivery console
description: Set up, operate, and deploy the unified Cloudflare delivery console.
---

The browser console lists verified uploads, selects a bundle, enables or
disables distribution, and can request a forced reload. It never receives R2
credentials, the CLI API key, or the RSA private key.

## One-shot Cloudflare setup

Put the private key matching the mobile public key in
`apps/console/.dev.vars` as `DELIVERY_SIGNING_PRIVATE_KEY`, then run:

```sh
pnpm lynx console setup --username your-name
```

The command uses Wrangler login, asks for a Cloudflare account and an R2 S3
access key with **Object Read & Write**, then creates or reuses D1/R2, deploys
the Worker, stores secrets, applies migrations, and writes ignored `.env.lynx`.
See [Cloudflare Worker setup](/managed-delivery/cloudflare-worker/#first-time-cloudflare-setup)
for the required signing PEM, the exact R2 Dashboard token, and the generated
environment values.

```sh
# Host team: prepare, build native app, then register
pnpm lynx host prepare
pnpm lynx host register

# Mini-app team: build and upload independently
pnpm lynx release
```

`.env.lynx` contains the Worker URL, CLI API key, R2 S3 credentials, and
console login. A feature team that only publishes bundles needs those upload
credentials; it does not need Cloudflare dashboard access or the signing key.

In the Console, first create the host app and mini-app IDs. After the host has
registered a build, open its mini app, select a compatible bundle, then enable
it. Use force only when a currently mounted feature should reload after local
verification.
