The browser console lists verified uploads, selects a bundle, enables or
disables distribution, and can request a forced reload. It never receives R2
credentials, the CLI API key, or the RSA private key.

## One-shot Cloudflare setup

Deploy from the Expo **host app** repository. The CLI packages this Console,
the Worker, and migrations, so an installed app does not need this monorepo.

```sh
lynx keys generate
lynx console setup
```

The first setup command creates a commented `.env.lynx` and stops. Fill the
resource names, Console username/password, and R2 S3 Object Read & Write
credential, then run `lynx console setup` again. Wrangler opens browser login
and account selection when `CLOUDFLARE_ACCOUNT_ID` remains a placeholder.
Setup creates/reuses D1 and R2, deploys the Worker, stores secrets, applies
migrations, and writes the deployment URL/API key into `.env.lynx`. See
[Cloudflare Worker setup](/managed-delivery/cloudflare-worker/#first-time-cloudflare-setup)
for the complete host configuration.

```sh
# Host team: embed once, prepare/register, then build the native app
pnpm lynx host embed ../mart
pnpm lynx host prepare --register

# Mini-app team: build and upload independently
pnpm lynx release
```

`.env.lynx` contains the Worker URL, CLI API key, R2 S3 credentials, and
console login. A feature team that only publishes bundles needs those upload
credentials; it does not need Cloudflare dashboard access or the signing key.

In the Console, first create the host app and mini-app IDs. After the host has
registered a build, open its mini app, select a compatible bundle, then enable
it. Use force only when a currently mounted feature should reload after local
verification.
