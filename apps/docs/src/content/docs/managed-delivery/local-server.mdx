---
title: Local Console and Worker
description: Run the same Console and Worker contract locally before deploying to Cloudflare.
---

The local environment is the Console plus a Wrangler Worker runtime. It uses
local D1/R2-compatible storage and the same public deployment route as the
deployed Worker:

```text
GET /v1/:appId/:feature
```

Start it from the repository root:

```sh
pnpm lynx console
```

The local Worker requires `apps/console/.dev.vars` with these values:

```dotenv
INITIAL_ADMIN_USERNAME=your-name
INITIAL_ADMIN_PASSWORD=choose-a-local-password
INITIAL_ADMIN_API_KEY=lynx_live_local_key
AUTH_SESSION_SECRET=random-local-secret
DELIVERY_SIGNING_PRIVATE_KEY=your-local-private-key
LOCAL_UPLOADS=true
```

The root command uses `INITIAL_ADMIN_API_KEY` automatically for local release
uploads. Do not commit `.dev.vars`.

Local D1/R2 state persists below `apps/console/.wrangler/delivery-worker-v2`.
Wrangler owns the exact SQLite filename. In TablePlus, open the newest SQLite
file in that directory to inspect the local tables.

Use [local iPhone testing](/managed-delivery/local-testing/) for the device
flow, or [Cloudflare Worker](/managed-delivery/cloudflare-worker/) to deploy
the same model remotely.
