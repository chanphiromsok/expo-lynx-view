---
title: Embedded and remote lifecycle
description: How managed delivery preserves instant local rendering and native compatibility.
---

The managed source chooses a local bundle before it contacts the Worker:

```text
compatible pending release → compatible active release → embedded baseline
```

Every installed release has a completion marker containing the native runtime
fingerprint. A marker that differs from the current app's fingerprint is
ignored, so a new native app build starts its embedded baseline rather than an
incompatible old cache.

After Lynx has produced its first screen, the app checks:

```http
GET /v1/:appId/:feature
lynx-runtime-version: <Expo project fingerprint>
```

The Worker signs a response for that exact runtime. Mobile verifies its
signature, feature, runtime, revision, and ETag before it can download an R2
ZIP.

| Console state | Existing installed release | Device without one |
| --- | --- | --- |
| `enabled: true`, `force: false` | Keeps rendering it and stages the selected update | Renders embedded, downloads and stages update |
| `enabled: true`, `force: true` | Reloads a mounted matching feature after verification | Stages until a matching view is mounted |
| `enabled: false` | Keeps the compatible verified cache | Uses embedded baseline |

`enabled: false` stops new distribution; it never remotely deletes a verified
release. During an App Store rollout, keep one deployment for each installed
runtime. The Console scopes them by `(appId, feature, platform,
runtimeVersion)`. `runtimeVersion` is an internal opaque native-compatibility
identity. A bundle's **Active** label applies only to the platform/runtime
selected in the Console.

```text
Host v1 asks for runtime A → only A deployment can be returned
Host v2 asks for runtime B → only B deployment can be returned
No B registration or selection → signed disabled B → embedded B bundle
```

Registering a host build and uploading a bundle never selects or enables it.
`force: false` stages a download for the next feature open; `force: true`
reloads a mounted matching feature only after installation verifies.
