---
title: Local delivery troubleshooting
description: Diagnose local Console, Worker, CLI upload, and iPhone connection failures.
---

## CLI cannot reach the Worker

Start the local environment and retry:

```sh
pnpm lynx console
pnpm lynx release
```

For a remote Worker, confirm `LYNX_DELIVERY_SERVER` is the canonical public
deployment URL, such as `https://worker.workers.dev/v1/default/delivery`, and
and that `LYNX_DELIVERY_API_KEY` is present in your ignored `.env.lynx`.

## R2 upload returns 403

The CLI uploads from your machine. Check the R2 S3 account ID, bucket, access
key ID, and secret access key in `.env.lynx`; the access key needs write access
to that bucket. The mobile app never receives these credentials.

## iPhone cannot connect

For local testing, use your Mac's current LAN IP in the build-time endpoint,
not `localhost`. Check Wi-Fi, firewall, VPN, and that the Worker listens on
`0.0.0.0`. Plain HTTP additionally needs an internal Release build compiled
with `LYNX_ALLOW_LOCAL_MANAGED_RELEASE=1`.

## A published update does not appear

The Console must select and enable the uploaded bundle for the exact
`(appId, feature, platform, runtimeVersion)` scope. **Active** means active only
for the runtime currently selected in Console. With force disabled, close and
reopen the feature after it stages.

`no-update` at revision 1 means the Worker has no matching registered
deployment for the runtime sent by that device. Compare the runtime in the
host's embedded `registry.json` with the Console selection. The host team
should run `lynx host prepare --register`, then build and install that exact
host without changing native inputs in between.
